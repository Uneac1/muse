# Muse UI 优化整理交付

## 推荐方向
采用“白底产品化操作台”作为统一方向，保留现有 `Today` 的报刊气质，但把它降为局部表达，不再主导全站。优先先做 `Today + Codex + Header + Sidebar` 四块基准面，验证后再横向清理其他页面。

## 第一优先级
1. 统一视觉 token
2. 压缩首页 hero，高价值任务前提
3. 固定卡片密度模板

## Token 收口建议

### 色彩
- 主色只保留一套：`primary=teal`
- 强调色只保留一套：`accent=amber`
- 信息状态尽量压成 `success / warning / danger / neutral` 四组
- 禁止页面级再私自引入 `cyan / sky / violet` 作为主视觉族

### 圆角
- 大容器：`rounded-[20px]`
- 普通卡片：`rounded-[16px]`
- 小控件 / 输入 / 按钮：`rounded-[12px]`
- 禁止同屏混用 `18/20/22/28`

### 阴影与边框
- 主卡片以浅边框分层，阴影只做弱辅助
- light 模式减少玻璃感和 blur 厚度
- 强调块优先靠底色差，不靠更重阴影

## 页面整理建议

### Today 首页
- 首屏保留一个 hero，但高度压到只承担“今日摘要 + 主行动”
- `Today / Inbox / 异常` 三列优先级要明确，首屏先看到任务，不先看到装饰
- 统计卡后移到第二屏或折叠区
- 右栏卡片高度控制一致，避免视觉重心飘到右上

### Codex / Token 工具页
- 顶部只保留一个主任务锚点，例如“当前异常 / 待同步 / 待处理账号”
- 统计、列表、状态、操作不要同时抢第一层级
- 列表卡拆成固定结构：标题区、状态区、动作区

### Header / Sidebar
- Header 图标按钮统一成同一尺寸、圆角、边框规则
- Sidebar 分组标题减小字距，正文尺寸略升一级
- 当前页高亮规则统一成“底色 + 文字强调”，不要再额外叠加多种描边

## 组件模板

### 概览卡
- 用于单条关键状态
- 结构：标题 / 数值或状态 / 一条解释 / 单主操作

### 列表卡
- 用于账号、邮件、异常项
- 结构：标题行 / 元信息行 / 状态标签 / 右侧动作

### 详情卡
- 用于 Runtime、报纸、长摘要
- 结构：顶部导航 / 主体内容 / 底部操作
- 必须支持展开，不允许依赖固定矮高度截断正文

## 前端落地顺序
1. 先清 `web/src/index.css` 的圆角、阴影、卡片和按钮基类
2. 再改 `Today` 首页首屏层级
3. 然后清理 `Header` 与 `Sidebar`
4. 最后统一 `Codex` 和其他工具页局部色板

## 验收标准
- light 模式下页面第一眼更白、更稳，不再糊成一片
- 同层级按钮外观一致，主次关系稳定
- `Today` 首屏无需滚动即可看到主任务
- `Codex` 页能在 3 秒内看懂“现在先处理什么”
