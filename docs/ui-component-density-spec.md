# Muse 组件态与页面密度细化

## 推荐方案
采用“低装饰、高行动密度”的产品化方案。核心不是再增加设计语言，而是把 `Today` 首页和 `Codex` 工具页的第一屏都收成一个明确主任务面板，加两到三个辅助块，避免并列抢注意力。

## 1. 首屏层级规则

### Today
首屏只允许三层视觉层级：

1. 第一层：`Today Hero`
2. 第二层：`Inbox / Issues / Next Step`
3. 第三层：弱化统计与资源健康

限制：
- 首屏主 hero 高度控制在 `280px - 340px`
- Hero 内不超过 1 个主标题、1 个摘要、1 组主行动、3 个以内辅助状态
- 第一屏禁止再放第二个大 hero
- 第一屏总卡片数建议 `4 - 6` 张，超过即视为密度失控

### Codex
首屏只保留一个主任务锚点，其他信息全部作为辅助：

1. 第一层：`主任务锚点卡`
2. 第二层：`待处理队列 / 当前状态 / 最近异常`
3. 第三层：背景统计和资源分布

限制：
- 首屏必须在 3 秒内回答“现在先处理什么”
- 所有统计数字不得比主任务标题更醒目
- 首屏主操作按钮只允许 1 个实心主按钮，其他一律降级

## 2. 页面密度规则

### 概览页密度
- 横向栅格优先 `12 columns`
- 主列占比 `7`，辅列占比 `5` 或 `4`
- 卡片内正文默认不超过 4 行
- 同一块内按钮不超过 2 个

### 列表页密度
- 单条列表高度建议 `72px - 96px`
- 元信息最多两行
- 标签最多 2 个可见，其余折叠成 `+N`
- 批量操作不进入单条首行

### 详情页密度
- 正文宽度优先 `680px - 760px`
- 长文本默认摘要 3 行，用户可展开
- 时间线类内容优先纵向展开，不用宫格式小卡切碎

## 3. 组件态细化

### 按钮
只保留三种语义：
- 主按钮：实心 `primary`
- 次按钮：浅底或描边
- 危险按钮：仅 destructive 场景

状态：
- default
- hover
- active
- disabled
- loading

规则：
- 同一容器只允许 1 个主按钮
- `loading` 时保留原宽度，避免跳动
- 图标按钮统一 `40x40`

### 卡片
只保留三套：

#### A. Hero Card
- 用途：首屏主任务
- padding：`24 - 28`
- 标题：`28/32`
- 摘要：`14/22`
- 主操作区始终贴近标题信息，不沉到底部

#### B. Summary Card
- 用途：Inbox、Issues、Quick Link
- padding：`18 - 20`
- 标题：`16/24`
- 元信息：`12/18`

#### C. List Row Card
- 用途：账号、任务、异常行
- padding：`14 - 16`
- 布局：左侧内容，中间状态，右侧动作

### 标签 / 状态
- `critical`：红
- `warning`：琥珀
- `success`：青绿
- `neutral`：灰蓝

规则：
- 标签仅承担状态识别，不承担主视觉装饰
- 同一卡片状态标签最多 2 个

### 输入框
- 高度统一 `40` 或 `44`
- 默认浅底，不做重玻璃效果
- focus 只强化边框与 ring，不额外加 glow

## 4. Today Hero 压缩方案

### 目标
把“品牌气质强于任务效率”改成“任务效率优先，品牌气质退居辅助”。

### 建议结构
- 左侧 `65%`
  - 标题：今天最该推进的一件事
  - 一句 AI 摘要
  - 主按钮 + 次按钮
  - 3 个以内关键状态 chip
- 右侧 `35%`
  - 今日数量摘要
  - 最近同步时间
  - 风险提示 1 条

### 删除项
- 删除过长导语
- 删除多余装饰徽章
- 删除第二组并列大数字

### 保留项
- 保留报刊感标题字体，但只用在标题
- 保留轻微底纹与渐变，但透明度下调

## 5. Codex 主任务锚点方案

### 核心问题
当前 `Codex` 页是“信息都重要”，所以没有真正最重要的信息。

### 目标结构
- 上方一张 `主任务锚点卡`
- 下方两列：
  - 左：待处理账号 / 队列
  - 右：最近异常 / 系统状态

### 主任务锚点卡内容
- 主标题：当前最需要处理的对象或风险
- 次描述：为什么现在处理
- 主按钮：立即处理
- 次动作：查看全部
- 右侧辅助信息：
  - 影响范围
  - 最近更新时间
  - 风险级别

### 文案规则
- 标题必须是动作导向，不写抽象标题
- 示例：`3 个账号待重新同步` 优于 `账号状态概览`
- 示例：`1 个高风险 token 今日过期` 优于 `Token Dashboard`

## 6. 响应式规则
- `>=1280`：Hero 左右双区
- `768-1279`：Hero 仍双区，但右侧摘要缩成单列
- `<768`：Hero 变单列，主操作提前，状态 chip 换行
- 移动端首屏卡片数控制为 `3 - 4`

## 7. 前端实现提示
- 先抽 `hero-card / summary-card / list-row-card`
- 再抽统一按钮与状态标签
- 最后重排页面，而不是先在页面里散改样式
