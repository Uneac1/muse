# Muse UI 二次校准复核清单

适用范围：
- `Today`
- `Codex`
- `Header`
- `Sidebar`

复核原则：
- 先看层级是否清楚
- 再看密度是否收束
- 最后看组件态是否统一

## A. Today 首屏

### 1. Hero 压缩是否成立
- [ ] 首屏只存在一个主 hero
- [ ] hero 高度落在 `280px - 340px`
- [ ] hero 内只有一个主结论，不存在第二组抢眼大数字
- [ ] 主按钮只有一个，次按钮不抢主按钮权重
- [ ] 辅助状态 chip 不超过 3 个
- [ ] 摘要足够短，首屏不出现冗长导语

### 2. 首屏层级是否清楚
- [ ] 第一眼先看到“今天先做什么”，不是先看到装饰或统计
- [ ] `Inbox / Issues / Next Step` 是 hero 下的第二层，而不是并列第一层
- [ ] 次级统计已后移或弱化，不与主任务竞争

### 3. 页面密度是否受控
- [ ] 首屏总卡片数控制在 `4 - 6`
- [ ] 单卡信息层级不超过标题 / 元信息 / 操作三层
- [ ] 右侧卡片高度与主区关系稳定，没有明显失衡

## B. Codex 首屏

### 1. 主任务锚点是否明确
- [ ] 首屏存在且只存在一个主任务锚点卡
- [ ] 主标题是动作导向文案，不是抽象模块名
- [ ] 用户能在 3 秒内回答“现在先处理什么”
- [ ] 统计数字没有比主任务标题更醒目

### 2. 信息是否服务于主任务
- [ ] 待处理队列是主任务的展开，而不是独立主题
- [ ] 最近异常和系统状态是辅助说明，不反客为主
- [ ] 主操作按钮只有一个实心主按钮

### 3. 密度是否收束
- [ ] 列表行高度统一
- [ ] 标签数量受控，没有一行堆满状态
- [ ] 卡片 padding 与间距遵守统一节奏

## C. Header / Sidebar

### Header
- [ ] 图标按钮尺寸统一
- [ ] 按钮圆角、边框、hover 规则一致
- [ ] 顶栏没有出现多个同级强调按钮

### Sidebar
- [ ] 当前页高亮规则统一
- [ ] 分组标题字距不过度拉开
- [ ] 导航字号与主体区可读性匹配

## D. 组件态统一

### 按钮
- [ ] 主按钮 / 次按钮 / 危险按钮三套语义清楚
- [ ] disabled / loading / hover / active 都有一致规则
- [ ] 同一容器只有一个主按钮

### 卡片
- [ ] `hero-card / summary-card / list-row-card` 三类边界清楚
- [ ] 圆角没有再次回到 `18/20/22/28` 混用
- [ ] 阴影与边框轻重一致

### 标签与状态
- [ ] 状态色只承担识别，不承担装饰
- [ ] 同一卡片可见标签不超过 2 个

## E. 响应式
- [ ] 宽屏下主列和辅列关系稳定
- [ ] 平板宽度下首屏没有挤压主任务锚点
- [ ] 移动端首屏卡片数压到 `3 - 4`
- [ ] 移动端按钮和 chip 可以自然换行

## F. 结论规则

若以下任一项不满足，则本轮视觉收束不通过：
- Today 首屏仍像装饰性首页，而不是行动首页
- Codex 首屏仍无法在 3 秒内回答“先做什么”
- 按钮、卡片、标签三套组件态仍然混乱

## G. Tokens 定向补充

### 1. 按钮层级
- [ ] `/tokens` 顶部操作区只有 1 个主按钮
- [ ] 账户卡片内同步 / 编辑 / 重授权不会同时都像主按钮
- [ ] 弹窗底部只有保存是主按钮，关闭 / 取消保持次级

### 2. 卡片层级
- [ ] 账户卡、余额卡、详情卡都仍属于同一套 `Surface` 体系
- [ ] 选中态靠边框和底色表达，不额外长出第二套强调样式
- [ ] 亮色模式下卡片层级主要靠边框、底色和字号，不靠重阴影

### 3. 状态语义
- [ ] `primary / success / warning / danger / neutral` 在 `/tokens` 中视觉可区分
- [ ] 成功态不与信息态混成同一颜色语气
- [ ] 错误标签和错误说明优先级高于普通状态，但不演变成主 CTA

### 4. 弹窗密度
- [ ] `TokenAccountDialog` 首屏不拥挤，接入方式按钮、字段区和 OAuth 区块有明确分段
- [ ] 同屏表单控件高度、圆角、边框一致
- [ ] 长文本输入区与普通输入区的节奏一致，没有额外样式分叉
