# Muse UX 优化方案

## 目标
把 Muse 从“功能很多但注意力分散”的后台，收成“先告诉你现在该做什么，再给你证据和入口”的工作台。

## 核心问题
- 首页与工具页都还存在多中心竞争
- 统计、状态、动作经常同级出现
- 用户能看到很多信息，但不总能立刻判断下一步
- `Codex`、`Today`、导航区的交互心智还没有完全统一

## 推荐方向
采用统一的“主任务锚点 + 次级证据 + 后移统计”结构。

## 第一阶段

### 1. Today
- 首屏只保留一个真正第一层焦点
- 顶部 hero 继续压缩，只承担背景与摘要
- 主焦点卡明确：
  - 现在先做什么
  - 为什么先做
  - 立即去哪里做
- `Inbox / 异常 / Next Step` 作为第二层证据区

### 2. Codex
- 首屏改成“当前切换风险 / 当前待处理账号 / 当前切换原因”三者围绕一个主任务锚点展开
- 自动切换相关说明进入辅助说明区，不与主操作抢层级
- 图表和统计后移，不再和主任务并列

### 3. 全局导航
- Header 保留搜索、AI、主题切换，但只保留一个高强调入口
- Sidebar 保持单一激活态，不再制造第二视觉中心

## 第二阶段

### 1. 统一交互反馈
- 所有主动作提供一致 loading / disabled / success 反馈
- 状态标签只表达状态，不承担装饰
- 当前页、当前账号、当前主操作都采用统一高亮规则

### 2. 降低理解成本
- 每个关键页面首屏都要能在 3 秒内回答：
  - 这里是什么
  - 现在先做什么
  - 做完去哪里

### 3. 减少页面抖动
- 避免切换和刷新后主区块大幅跳动
- 保持按钮宽度、卡片高度、列表密度稳定

## 对 fullstack 的落地顺序
1. 先稳住 `Codex` 自动切换逻辑和状态表达
2. 再改 `Codex` 首屏主任务锚点
3. 然后继续 `Today` 首屏层级收束
4. 最后统一 `Header / Sidebar / 全局按钮与卡片`

## 验收标准
- 用户进入 `Today` 后能立刻知道今天先做什么
- 用户进入 `Codex` 后能立刻知道现在是否要处理切换问题
- 所有首屏都不再像并列统计台
- 主按钮、次按钮、状态标签、卡片密度在全站一致
