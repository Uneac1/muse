## 白底产品化重构 + Runtime 全局内嵌方案

### Summary
把 Muse 的整体 UI 收成“白底为主、深色可切换”的产品级操作台，同时把 Runtime 从现在的独立浮层/局部窗口思路，升级为全局内嵌式运行时体验。核心目标是三件事：默认视觉更轻、更白、更像正式产品；`/ai` 页的 `Muse Runtime Surface` 成为 Runtime 的主承载面；所有关键 Runtime 信息尤其是实时动作轨迹，改成自适应可展开、可完整阅读，而不是被固定高度和裁切策略压缩。

### Key Changes
#### 1. 全局视觉系统改成白底优先
- 继续保留右上角明暗切换，但把默认 light theme 再提纯到更干净的白底体系，减少当前偏米色和雾面厚度。
- 调整全局 token，重点收口 `background`、`card`、`secondary`、`border`、`shadow`，让 light 模式更接近产品后台而不是杂志感过强的 editorial surface。
- 降低全局 glow、grid、noise 的存在感，让它们只做气氛，不抢信息层级。
- 统一 `/ai` 页、侧边栏、Header、卡片、输入区和按钮的 light mode 对比度，确保视觉重心在内容和动作，不在装饰。

#### 2. Runtime 改为全局内嵌，不再走“独立窗口心智”
- 以 `/ai` 页为 Runtime 主阵地，把 `Muse Runtime Surface` 提升为页面顶层核心区块，放在 AI 工作台主内容流前段，不再让 Runtime 像补充面板。
- 全局浮层助手不再承担“Runtime 容器”职责，保留它作为轻量入口/快捷交互，但不再承载完整运行时阅读任务。
- 如果存在当前 Runtime 相关的独立遮罩/抽屉/弹层入口，调整为跳转或锚定到 `/ai` 页内的 Runtime 主面板，而不是继续开新层。
- Runtime 与聊天、账号池、线程列表的关系重组为“Runtime 主视角 + 会话/账号辅助区”，避免用户在不同层之间切换上下文。

#### 3. Muse Runtime Surface 重排为自适应阅读工作区
- 将现有 tab 面板从“切换后只展示少量 slice”改成“大面板 + 可扩展分区”结构。
- `实时动作轨迹` 升级为完整时间线视图，不再只 `slice(0, N)`；默认显示最近一批记录，并提供“展开更多 / 全量查看 / 收起摘要”。
- 时间线容器改为自适应高度：
  - 桌面端优先占据主列剩余空间，最小高度明确，允许内部滚动。
  - 宽屏下使用上下分区或双列，但保证轨迹列优先更宽。
  - 窄屏下改成单列堆叠，避免因为并排信息过多压缩轨迹内容。
- 关键运行时区块都要从固定小卡片思路改成可伸缩面板，尤其是：
  - 实时动作轨迹
  - 全量事件流
  - 异常与恢复
  - 记忆层 / 技能画像
- 对长文本字段做更好的阅读策略：摘要默认两到三行，支持展开；时间、来源、scope、eventType 作为次级元信息固定排版，不挤占正文。

#### 4. `/ai` 页信息架构重组
- 顶部保留 AI 工作台 hero，但压缩装饰信息密度，让第一屏直接进入 Runtime 主工作区。
- `Shared Runtime` 区块改名和层级优化，标题与说明文案更明确表达“这是 Muse 的长期运行界面，不是单独弹窗工具”。
- 当前四类 tab `概览 / 观察 / 记忆 / 恢复` 继续保留，但改成更强的信息导航，而不是内容分页器：
  - 概览：总览 + 关键状态卡 + 最近轨迹摘要
  - 观察：页面熟悉度 + 全量事件流
  - 记忆：短期/长期记忆 + 画像/技能
  - 恢复：异常、自愈、能力权重、恢复历史
- 账号池如果继续保留遮罩形态，只作为配置编辑器，不再和 Runtime 主阅读抢层级；Runtime 本身必须完全在页面内看完。

#### 5. 交互细节
- 为 Runtime 主区增加快速定位交互：点击 tab 时滚动并聚焦对应分区，而不是强制只显示该分区。
- 增加“轨迹密度”与“展开状态”本地记忆，避免用户每次都要重新展开。
- 对 `运行中`、`采集中`、`整理中` 状态做更明显但不突兀的 inline 反馈，减少目前 scattered badge 的感受。
- 保持 light/dark 双主题一致的层级和可读性，深色只是配色变化，不改变布局逻辑。

### Interfaces / Behavioral Changes
- 不新增后端 API；主要是前端布局、状态呈现与本地 UI 状态管理重构。
- 前端状态层需要新增少量 UI state，用于：
  - Runtime 分区展开/收起
  - 轨迹列表默认条数与“查看更多”
  - 桌面/移动端布局模式适配
  - 全局入口跳转到 Runtime 面板的锚点或激活分区
- `MuseCopilot` 的职责会收窄为轻助手入口；完整 Runtime 阅读与操作以 `/ai` 内嵌页为准。

### Test Plan
- `/ai` 在 light mode 下首屏应以白底产品界面为主，Runtime 主区无需弹窗即可完整可见。
- 右上角 theme toggle 在 light/dark 之间切换后，Runtime 主区、时间线、按钮、输入区都保持可读。
- 宽屏下实时动作轨迹应明显比当前更长、更完整，至少能连续阅读多条记录而不被卡片裁断。
- 中等屏宽和移动宽度下，Runtime 自动改为单列或更宽主列，不出现正文被压窄看不全。
- 从全局入口进入 Runtime 时，不再弹出独立完整窗口，而是落到页面内嵌 Runtime 视图。
- `npm run build`、`npm run verify:ui`、`npm run verify:core` 必须继续通过，确保这轮重构不破坏现有 smoke 链。

### Assumptions
- 默认采用“白底优先、深色可切换”的产品后台方向，不回退到当前更偏米色/厚玻璃感的主视觉。
- “全局都内嵌”解释为：完整 Runtime 体验统一收束到页面内嵌主界面，不再依赖独立浮层承载主要阅读任务；轻量浮层入口可以保留，但不再是主容器。
- 本轮重点是 Runtime 产品化信息架构、可读性和布局自适应，不引入新的后端能力或新的 Runtime 数据源。
