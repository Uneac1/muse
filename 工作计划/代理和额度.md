## 内置代理自愈与额度同步闭环补强计划

### Summary
把当前“能跑，但掉一次就靠运气恢复”的内置代理链路升级成真正的自愈基础设施，目标是让 `Token 管理 -> 自动同步 -> OpenAI 官方额度抓取` 在页面刷新、节点失效、内核退出、状态文件异常、默认代理切换后都能自动恢复，不再把临时故障直接暴露成用户错误。

本轮要补的不是单点报错，而是整条链的 6 个薄弱环节：
1. 内核掉线后只会失败，不会后台守护重拉。
2. OpenAI 校准只会选节点，不会做多阶段恢复。
3. 节点健康没有缓存和降级策略，容易反复抖动。
4. 自动同步会持续打失败账号，缺少错误分级和退避。
5. 前端会在页面刷新/聚焦时频繁触发同步，但没有展示“后台恢复中”的状态。
6. `state.json` / 默认代理 / 内核代理记录之间缺少一致性修复流程。

### Key Changes
#### 1. 后端把内置代理改成“守护态服务”，而不是“按需启动工具”
- 在 `ProxyKernelService` 上增加守护循环或健康巡检入口，由 `server.ts` 启动后常驻。
- 守护职责固定为：
  - 检查 `mixed-port`、`controller-port`、mihomo pid、默认代理指向是否一致。
  - 发现内核未运行时自动重启。
  - 发现默认代理丢失或切回外部代理时，恢复到“用户显式设置的默认代理”或“内置代理”。
  - 发现 `state.json` 缺失/损坏时，用运行态、MiSub 源和代理库信息重建状态。
- `ensureKernelBootstrapped()` 不再只是启动时跑一次，而是作为守护恢复子流程复用。

#### 2. OpenAI 校准流程升级成分层恢复
- `ensureOpenAiProxyReady()` 改成明确的四阶段：
  1. 保证内核运行。
  2. 保证有有效订阅源/分组源。
  3. 保证 OpenAI 分组存在且当前节点可选。
  4. 逐个测试候选节点并持久化最佳节点。
- 节点候选顺序固定为：
  - 用户手选节点
  - 当前激活节点
  - 偏好分组内节点
  - 分组全部节点
- OpenAI 自动择优节点优先级改为：
  - `🇸🇬 狮城节点`
  - `🇯🇵 日本节点`
  - `🇺🇲 美国节点`
  - `🇹🇼 台湾节点`
  - `🇭🇰 香港节点`
- 增加“校准失败后的二次恢复”：
  - 第一次失败：重新载入状态和代理组信息后重试。
  - 第二次失败：停止内核、重建 config、重启内核、再跑节点测试。
  - 第三次失败：返回结构化故障原因，而不是裸字符串。
- `testOpenAiHandshake()` 结果要区分：
  - 网络不可达
  - OpenAI 风控/地区拒绝
  - 本地代理端口不可用
  - 控制器无响应

#### 3. 节点健康与状态持久化补齐
- `state.json` 写入改成原子写：
  - 先写临时文件，再 rename 覆盖，避免 Windows 文件锁导致半写入。
- 增加内存态 `kernelRuntimeState`，避免所有逻辑都硬依赖磁盘状态文件。
- 新增节点健康缓存：
  - 记录最近成功的 `group -> node -> handshake result -> checkedAt`
  - 短时间内不要重复全量试节点
  - 对最近连续失败节点加冷却时间，避免每次同步都撞同一个坏出口
- `getStatus()` 返回扩展字段：
  - `health`
  - `lastSuccessfulNode`
  - `lastSuccessfulAt`
  - `recoveryState`
  - `lastRecoveryError`

#### 4. 自动同步从“轮询”补成“故障分级 + 退避”
- `TokenAutoSyncService` 增加错误分类：
  - `reauth_required`
  - `proxy_recoverable`
  - `network_transient`
  - `provider_blocked`
  - `unknown`
- 行为规则固定：
  - `reauth_required`：关闭该账号自动同步。
  - `proxy_recoverable`：不关账号自动同步，但本轮跳过并触发内置代理恢复。
  - `network_transient`：保留自动同步，按指数退避。
  - `provider_blocked`：保留账号，标记需要换节点或人工检查。
- 为每个账号增加同步退避元数据，至少要有：
  - `next_retry_at`
  - `failure_count`
  - `last_failure_kind`
- `auto-sync` 接口返回中补充：
  - 恢复动作是否已触发
  - 哪些账号被延迟重试
  - 哪些账号被暂停自动同步

#### 5. 前端把“自动恢复中”变成可见状态
- `TokenAnalytics.tsx` 不再只静默调 `/auto-sync`。
- 页面增加内置代理状态小条，显示：
  - 内核运行中 / 恢复中 / 失败
  - 当前 OpenAI 分组
  - 当前节点
  - 最近一次健康检查时间
- 当后端返回 `proxy_recoverable` 时：
  - 不弹红色系统错误
  - 显示“内置代理正在自动恢复并重试”
- 账号卡片错误文案要区分：
  - 账号授权失效
  - 节点/代理恢复中
  - OpenAI 地区/风控拒绝
- 保留手动“测试节点/同步”按钮，但默认依赖后台自愈，不要求用户先手动处理。

#### 6. 默认代理和内置代理的职责边界补齐
- `ProxyService.getAgent()` 当前只会“发现内置代理不可用就跳过”，这会导致请求直接走空代理或外部代理，行为不稳定。
- 改成规则化：
  - 如果默认代理是内置代理且不可用，先请求 `ProxyKernelService` 恢复。
  - 恢复成功再返回内置代理 transport。
  - 恢复失败才降级为空代理，并带上明确失败原因。
- 明确“内置代理”和“普通代理”的优先级策略：
  - OpenAI 官方额度抓取优先内置代理。
  - 其他 API 继续走用户默认代理。
  - 不允许因为普通代理默认值变化，把 OpenAI 同步静默切走。

### Public / Interface Changes
- 扩展 `ProxyKernelStatus` 返回字段：
  - `health: 'healthy' | 'recovering' | 'degraded' | 'failed'`
  - `lastSuccessfulNode: string`
  - `lastSuccessfulAt: string | null`
  - `recoveryState: string`
  - `lastRecoveryError: string`
- `POST /api/tokens/auto-sync` 返回新增字段：
  - `recoveryTriggered: boolean`
  - `recoveryMessage?: string`
  - `delayedAccounts?: number[]`
- `TokenAccount` 同步元数据新增字段：
  - `next_retry_at`
  - `failure_count`
  - `last_failure_kind`
- 前端 `TokenAccountView` / `ProxyKernelStatus` 类型同步补全以上字段。

### Test Plan
#### 后端恢复链
- 内核未运行时调用 OpenAI 同步，应自动拉起内核并完成节点校准。
- `state.json` 缺失时，自动同步仍能恢复运行，不返回 500。
- `state.json` 被锁/写失败时，只记告警，不阻断同步主流程。
- 当前节点失效时，自动切换到下一个可用节点并持久化。
- 所有候选节点都失败时，返回结构化 `provider_blocked` 或 `proxy_recoverable` 错误。
- 节点优先级验证为：新加坡先于日本，日本先于美国。

#### 自动同步
- 页面刷新触发 `/auto-sync` 时，不会因为代理暂时掉线直接把所有账号标红。
- `refresh_token_reused` 账号会停自动同步。
- `proxy_recoverable` 账号不会停自动同步，只进入退避。
- 连续失败账号会按退避时间跳过，不会高频打 OpenAI。

#### 前端表现
- `/tokens` 页面首次进入时能看到内置代理状态。
- 自动恢复中显示提示，不弹系统级 500 toast。
- 账号卡片错误类型区分正确。
- 手动同步与自动同步的结果文案一致，不互相冲突。

### Assumptions
- 继续使用 mihomo 作为唯一内置代理内核，不新增第二套内核。
- OpenAI 官方额度抓取仍然只针对 `openai_codex` 账号走内置代理优先策略。
- 自动择优节点默认优先级固定为“新加坡 > 日本 > 美国 > 台湾 > 香港”。
- 前端仍以 `/tokens` 为唯一额度总控页，不拆新页面。
