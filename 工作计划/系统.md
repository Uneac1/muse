# Muse 全局自洽收口实施计划

## Summary
以“稳定优先”为总原则，先把系统从“能构建、能冒烟、但运行时大量假成功和隐性降级”的状态收口到“失败可观察、恢复可追踪、前后端语义一致”的产品级基线，再在这条稳定基线上完成 AI 原生对话、代理自愈闭环、报纸工作台化、Runtime 内嵌化四条主线。

本轮默认采用：
- 先稳定运行时与错误语义，再做 UI/体验收口。
- 报纸阅读主入口切为右侧抽屉，`/newspaper/read` 仅保留兼容。

## Key Changes
### 1. 聊天链路去 Muse 壳，Runtime 改为最小隐式层
- 重构 `server/src/services/AiChatService.ts` 的提示词拼接逻辑，去掉会改变模型人格和回答风格的 Muse 包装，把聊天输入收口为：
  - 纯用户消息
  - 最小运行时事实
  - 工具注册与调用结果
  - 安全/执行元数据
- 保留账户回退、协议识别、原生 tools、模型 fallback，但它们只作为运行时底座，不再污染主对话语义。
- 明确区分两类数据流：
  - `chat_session`：用户消息、模型原生回复、线程历史
  - `agent_runtime`：观察、记忆、动作、恢复、事件流
- 调整 `/api/ai/accounts/:id/chat` 及相关返回结构，保证前端仍能拿到 `fallbackAccount`、`toolDetails`、`responseMeta`，但展示文案改为“共享运行时工具/恢复信息”，不再叫 Muse 执行壳。
- 校正现有验证脚本，让“返回 200 但内容是本地降级/全账号失败”不再被视为完全成功。

### 2. 内置代理、自愈、额度同步做成单一恢复闭环
- 以 `server/src/services/ProxyKernelService.ts` 为唯一代理真相源，补齐：
  - 守护常驻启动
  - `state.json` / 运行态 / 默认代理一致性修复
  - OpenAI selector 分层恢复
  - 节点健康缓存与失败冷却
- 以 `server/src/services/TokenAutoSyncService.ts` + `TokenQuotaService` 为同步编排层，保证：
  - `proxy_recoverable` 不再把账号直接打成最终失败
  - `reauth_required`、`network_transient`、`provider_blocked` 行为分流
  - 每个账号都持有 `next_retry_at`、`failure_count`、`last_failure_kind`
- 收口 `ProxyService.getAgent()` 行为：默认代理若是内置代理且不可用，先触发恢复，再决定是否降级。
- 扩展代理与同步接口，前端 `/tokens` 能直接显示：
  - 内核状态
  - 恢复状态
  - 最近可用节点
  - 自动恢复提示
- 把当前日志里出现的 TLS 握手失败、区域拒绝、账号回退等错误映射成结构化故障类别，不再只靠字符串提示。

### 3. 报纸模块改成状态型工作台，不再靠整页刷新维持
- 后端继续沿用 `server/src/services/NewspaperService.ts` 的 source/detail/AI 缓存与重试方向，但统一成三层状态机：
  - source：`ok | stale | failed | recovering`
  - detail：`pending | partial | ready | failed | recovering`
  - ai task：`pending | ready | failed | retrying`
- 前端 `web/src/pages/Newspaper.tsx` / `NewspaperReader.tsx` 收口为：
  - 报纸页主工作台
  - 右侧阅读抽屉主入口
  - `/newspaper/read` 兼容展示
- 本地工作台状态持久化至少覆盖：
  - 领域排序模式与手动顺序
  - 搜索词
  - 文章排序
  - 当前打开文章
  - 抽屉开关
  - 滚动位置
  - 当前 briefing insight 时间戳
- 总编台固定为全领域摘要，不随搜索直接缩水；搜索结果只影响次级视图摘要。
- 详情页不再用“摘要模式”掩盖全部失败，而是模块化展示正文、图片、回复、翻译各自状态。

### 4. Runtime 与 `/ai` 页收口成页面内嵌主界面
- 以 `web/src/pages/AiStudio.tsx` 为 Runtime 主容器，保留现有数据源，但重组为：
  - 主聊天区：原生模型对话
  - Runtime 主区：观察、事件流、记忆、恢复
  - 账号池与配置区：辅助面板
- 去掉强壳文案和“独立 Runtime 窗口心智”，全局入口统一落到 `/ai` 页面内嵌 Runtime 面板。
- 保留 `概览 / 观察 / 记忆 / 恢复` 导航，但改为页面内分区定位，不是切页式小卡片分页。
- 实时动作轨迹、全量事件流、异常恢复、记忆层都改成可扩展、自适应高度面板，不再 `slice(0, N)` 式压缩关键信息。
- 白底产品化视觉只在不破坏现有布局的前提下同步收口，放在稳定语义和结构之后完成。

## Public Interfaces / Data Changes
- 聊天返回补强并规范：
  - `responseMeta`
  - `fallbackAccount`
  - `toolDetails`
  - `degradedReason?`
  - `runtimeEventRefs?`
- 新增或补齐 Runtime 接口：
  - `GET /api/os/agent/runtime`
  - `GET /api/os/agent/memory`
  - `GET /api/os/agent/activity`
  - `GET /api/os/agent/events`
  - `POST /api/os/agent/mode`
  - `POST /api/os/agent/memory/compact`
- 扩展 `ProxyKernelStatus`：
  - `health`
  - `lastSuccessfulNode`
  - `lastSuccessfulAt`
  - `recoveryState`
  - `lastRecoveryError`
- 扩展 `/api/tokens/auto-sync` 返回：
  - `recoveryTriggered`
  - `recoveryMessage`
  - `delayedAccounts`
  - `pausedAccounts`
- 扩展报纸类型：
  - `NewspaperSourceStatus.status`
  - `NewspaperArticle.detailStatus`
  - `NewspaperArticle.readerStateKey`
  - `NewspaperArticleDetail.fulltextStatus/imageStatus/replyStatus/translationStatus`
  - `NewspaperBriefingAiInsight.coverage`

## Test Plan
- 构建与回归：
  - `npm run build`
  - `npm run verify:core`
  - 补一组“失败不是成功”的断言，修正现有过宽松 smoke
- AI 原生对话：
  - Codex、Gemini、Claude/兼容路由对同题回复风格应保留模型差异
  - 非工具场景请求体与响应链路中不应再出现 Muse 人设文本
- 代理与同步：
  - 内核未运行、节点失效、`state.json` 缺失/损坏、默认代理漂移时能自动恢复
  - `reauth_required` 会暂停自动同步
  - `proxy_recoverable` 只退避并触发恢复，不直接打爆红
- 报纸工作台：
  - 刷新后排序、搜索、滚动位、当前阅读文章可恢复
  - source/detail/AI 任一路失败时页面显示模块状态，不整页打回“摘要模式”
  - 阅读抽屉关闭后恢复原工作台上下文
- Runtime UI：
  - `/ai` 不依赖弹层即可完整阅读 Runtime
  - 时间线、事件流、异常恢复在桌面和窄屏下都可完整浏览
  - light/dark 切换不改变信息架构

## Assumptions
- 当前工作区已有大量未提交改动，实施必须以“增量收口”方式进行，不回滚用户现有半成品。
- 现有 `AgentAutonomyService`、`TokenAutoSyncService`、`PersonalMemoryIngestionService`、`AiMuseToolService` 等新增模块视为正在建设中的基础，不推翻重写，只做职责重排和语义校正。
- 第一阶段不追求彻底重构所有页面，只要求把 AI、代理、报纸、Runtime 四条主线的失败语义、恢复链、状态展示统一起来。
- `/newspaper/read` 保留兼容，但主交互以报纸工作台右侧抽屉为准。
