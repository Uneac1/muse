# Muse 终态全局自治重构计划：原生模型对话 + 全量记忆运行时

## Summary
把当前“模型被套壳成 Muse”的架构，重构成“两层分离、单窗口呈现”：

- 对话层：你看到和输入的，就是 `Codex / Gemini / Opus` 原生对话，不再有 Muse 人设、话术、框架式回复。
- 运行时层：后台独立的 Agent runtime 持续观察页面、工具、结果、异常和对话，维护一套全局共享的记忆库、技能库、页面知识库和工具经验库。
- 交互形态：仍保留单窗口混合体验，但聊天尽量原生；只有在需要动作、记忆检索或工具调用时，才通过最小隐式层接入运行时。
- 自治策略：先做“后台持续巡检 + 观察后执行”的分级自治；初始默认观察优先，后续可切到更高权限。
- 记忆策略改为全量记录，后期由 AI 自动整理、提纯、归档和压缩。

## Key Changes
### 1. 拆分“原生对话层”和“自治运行时层”
- 新的聊天链路不再把 `runtime_context`、Muse 行为引导、Muse 话术拼进用户消息文本。
- 保留一层不可见最小协议，只做：
  - 工具注册
  - 记忆检索注入
  - 安全/运行态元数据
- 明确禁止：
  - Muse 人设提示
  - “你是 Muse 执行层”这类角色包装
  - 框架式回复模板
- UI 上继续是一套窗口，但内部变成两个通道：
  - `chat_session`: 面向模型原生回复
  - `agent_runtime`: 面向观察、记忆、技能沉淀和动作执行

### 2. 建全局共享记忆库和技能库
- 记忆改为全量记录，默认纳入：
  - 页面观察结果
  - 工具调用记录
  - 任务结果
  - 失败与修复链
  - 异常与恢复事件
  - 你和模型的对话
  - 模型内部产生的高价值结论与计划
- 所有模型共享同一套：
  - 长期记忆库
  - 技能库
  - 页面知识库
  - 工具经验库
- 记忆分层：
  - `raw_event_log`: 全量原始记录，先收全
  - `short_term_observations`: 最近页面/工具/异常/对话轨迹
  - `long_term_memory`: 稳定结论、用户习惯、已验证方案
  - `skill_journal`: 成功动作模式、失败规避模式、修复 playbook
- 新增后台整理器：
  - 周期性从 `raw_event_log` 提炼长期记忆
  - 自动合并重复项
  - 自动降噪、归档、压缩低价值历史
  - 为每条长期记忆保留来源链路，确保可追溯
- 每次模型完成真实动作或形成高价值结论后，运行时自动：
  - 写入原始日志
  - 尝试提炼经验
  - 更新相关记忆/技能项
  - 为后续模型共享复用

### 3. 后台持续巡检机制
- 观察循环由四类事件共同驱动：
  - 页面切换
  - 工具执行结果
  - 前后端异常事件
  - 定时巡检
- 初始阶段默认 `observe-first`：
  - 页面熟悉
  - 工具熟悉
  - 结果对账
  - 异常识别
  - 记忆沉淀
- 执行升级分级：
  - `observe_only`: 只观察和沉淀
  - `guided_execute`: 只执行低风险、已有高置信经验的动作
  - `full_execute`: 后续开放全权限
- 运行时为每个页面维护“熟悉度/置信度”信号，作为执行放权依据。

### 4. 工具层改成“模型原生能力增强”，不是 Muse 壳
- 保留 provider-native tools，但语义改成“模型可用的共享工具库”，不是 “Muse 指令集人格壳”。
- 工具调用结果写入统一 action log，并可被任意模型读取。
- 工具与记忆检索在聊天层中的呈现原则：
  - 默认不可见
  - 仅在模型实际使用时参与
  - 不改变模型原生说话风格
- 当前已存在的工具枚举、alias 修正、账号池 fallback 继续保留，但降级为运行时底座，不再暴露成 Muse 框架感。

### 5. 前端呈现重做为“原生模型聊天 + 后台自治状态”
- 保留单窗口，但区分两块信息：
  - 主聊天区：模型原生回复
  - 侧边/底部状态区：后台自治观察、动作、记忆沉淀、异常恢复
- 去掉当前“全局 AI 手动执行模式 / Muse 全局控制面板”这类强壳文案。
- 模型切换后：
  - 对话对象直接变成对应模型
  - 共用全局记忆和工具库
  - 不切断共享知识
- 新增运行时可视化：
  - 当前观察页面
  - 最近沉淀的记忆/技能
  - 最近动作与结果
  - 当前自治级别（观察/引导执行/全执行）
  - 原始记录整理状态（待整理、已提炼、已归档）

## Public Interfaces / Data Shape
- 聊天接口保留现有账户入口，但语义调整：
  - `message`: 纯用户消息
  - `runtime_context`: 不再充当角色提示，只传页面事实和运行态元数据
- 新增或重构运行时接口：
  - `GET /api/os/agent/runtime`：当前自治状态、页面观察状态、当前级别
  - `GET /api/os/agent/memory`：共享长期记忆、短期观察、技能条目
  - `GET /api/os/agent/activity`：最近动作、异常、恢复、沉淀记录
  - `GET /api/os/agent/events`：原始全量事件流与整理状态
  - `POST /api/os/agent/mode`：切换 `observe_only / guided_execute / full_execute`
  - `POST /api/os/agent/memory/compact`：手动触发一次记忆整理/归档
- 记忆对象至少包含：
  - `layer`（raw/short_term/long_term/skill）
  - `scope`（global/page/tool/chat/recovery/task）
  - `source`
  - `confidence`
  - `lastUsedAt`
  - `shared=true`
  - `originRefs`（原始事件引用）
- 聊天结果保留 `fallbackAccount`、`museToolDetails` 这类执行信息，但前端展示语义改成“模型使用的共享工具结果”。

## Test Plan
- 原生对话验证：
  - 同一问题分别对 Codex、Gemini、Opus 发起聊天，回复风格应明显保留各自模型特征，而不是统一 Muse 腔。
  - 不执行动作时，请求和响应中不应出现 Muse 人设文本或框架式说明。
- 全量记忆验证：
  - 页面、工具、异常、聊天、修复记录都会进入原始事件流。
  - 低价值对话先允许进入 `raw_event_log`，后续由整理器归档，不应直接污染长期记忆。
- 共享记忆验证：
  - 用一个模型完成真实动作并沉淀记忆；切换另一个模型后，应能读取并利用该经验。
- 巡检与观察验证：
  - 页面切换、工具执行、异常上报、定时器均能触发观察日志。
  - `observe_only` 模式下不会产生真实高风险动作。
- 执行分级验证：
  - `guided_execute` 只允许低风险高置信动作。
  - `full_execute` 预留能力开关，但初期默认不启用。
- 记忆整理验证：
  - 重复、低价值、过旧内容会被压缩或归档。
  - 长期记忆能追溯回原始记录。
- 回归验证：
  - 账号池模型切换仍正常。
  - provider-native tool calling 不回退成文本壳。
  - 历史 tool alias 修正仍有效。

## Assumptions
- 单窗口混合体验保留，但内部必须拆成“原生聊天层 + 后台运行时层”。
- 默认采用“全局共享库”，不做模型私有记忆隔离。
- 默认采用“最小隐式层”，允许隐藏式工具注册、记忆检索和安全元数据，但不再加入 Muse 人设或行为包装。
- 第一阶段默认自治级别为 `observe_only`，并实现通向 `guided_execute` / `full_execute` 的完整架构，不在第一阶段直接默认全权限。
- 记忆默认先全量收集，再由 AI 整理；不在采集入口做强过滤。
- 当前已有账号池排序、原生工具调用、tool enum/alias 修正逻辑作为底座复用，不推翻重写。
